# 修仙开放世界：设计依据与第一阶段边界

更新：2026-10-21。本文区分正式方向、已实现的技术切片、临时占位规则和未来计划。代码状态以 TEST_REPORT.md 及同包源码为准。

## 1. 已正式确定的长期方向

以下来自用户要求，不代表本阶段已实现完整系统：

- 2D 俯视角像素风、即时战斗，参考《元气骑士》的简洁画面与低操作门槛；单机优先，未来才考虑联机。
- 玩家从凡人开始，修炼成长、探索、战斗、获得机缘和追求长生。修炼人生与自由冒险并重。
- 长期支持炼丹、交易、产业经营、护卫招募、宗门建设与势力发展。
- 世界规则硬核、残酷，操作本身保持易上手。NPC 与玩家遵守同一套核心世界规则；NPC 逐步具备独立目标、关系、经历与命运。
- 世界不只围绕玩家运转。玩家死亡不自动重置世界，上一世的历史与势力继续演化。
- 转世不自动继承上一世资产、实力或社会地位。玩家和 NPC 都可能随机获得残缺前世记忆，也可能没有。
- 零预算、免费工具、模块化、逐步验证；不在一个阶段实现全部社会模拟。

### 临时规则与正式设计的区别

沿用旧原型的初始「炼气 1 层」、每 100 修为升一层、每秒 12 修为。它们只是用于验证成长数据的占位，**尚未实现正式的凡人起步流程**；升级暂不改变伤害或生命。境界划分、突破资源、失败代价、寿元公式等未讨论，不自行确定。

R / 按钮会明确「重置测试场景」，恢复初始地图。这是保留的测试工具，**不是死亡自动重置，也不是转世**；不会被描述为正式世界规则。正式死亡状态保留当前世界。F9 读取此前快照允许回到旧状态，是本阶段验证持久化的手动测试能力，不代表已确定死亡后回档的正式玩法。尚未实现死亡后的新人生，因此目前死亡后只能查看状态、读快照或显式重置测试场景。

## 3. 存档边界

schema version=1，map_id=test_map_v1；文件为 Godot `user://stage1-save.json`。保存前校验，写完临时文件后替换旧文件；替换失败返回错误，不主动删除旧档。运行时缺失/损坏/版本不兼容存档均提示错误，不修改当前世界。

保存字段：玩家位置、生命、当前保护、攻击剩余冷却、修炼层数与修为；所有存活敌人的位置、生命、保护剩余时间及出生/回家位置。被击杀的敌人不写入，读取后不会刷新。死亡存档保留玩家 0 生命。

不保存短暂特效、已发射弹体、输入按键状态、动画帧；读取时清理这些瞬态。没有自动存档、多槽、云存档、加密、历史回滚、旧 schema 迁移或跨平台兼容承诺。不做离线推进。地图仍固定，变更地图障碍时应同步更新验证边界和 map_id。

## 4. 架构与运行

Godot 4.7.2 stable / GDScript / Compatibility (OpenGL)，无插件、外部服务或额外运行库。`scenes/main.tscn` 入口，`world.gd` 负责装配与 UI，不承载 NPC 社会决策。

| 模块 | 职责 |
|---|---|
| player.gd / enemy.gd | 输入移动、追击与角色装配 |
| combat.gd / projectile.gd | 攻击冷却、方向命中、弹体碰撞 |
| stats.gd | 通用生命、保护与 damaged / died 信号 |
| cultivation.gd | 修为与境界占位数据 |
| feedback.gd | 纯视觉效果；不计算伤害与成长 |
| game_state.gd | 当前场景生存/死亡状态 |
| save_store.gd | 快照版本、数据校验、文件读写 |
| world.gd | 地图装配、状态接线、快照采集与应用、UI |

本工作区双击 Start-Game.cmd；或 Godot 导入 project.godot 后按 F5。测试执行 Test-Project.ps1。移动项目后可向启动/测试脚本传 -GodotPath；细节见 README。

## 5. 未实现系统及后续边界

- 凡人出生、随机身世与正式成长：未来用角色生成器构造初始数据，不把规则写入 UI。
- 寿元与世界时间：未来独立时间/寿元模块，明确在线与离线推进规则后再实现。
- NPC 人生：未来将目标、关系、经历与决策分开；复用属性和成长规则，不先写空壳社会模拟。
- 转世与前世记忆：需要独立角色身份与持续世界身份、历史事件记录；继承禁止规则是正式方向，具体随机概率仍待设计。
- 领地、宗门、商会、护卫、外交、经济与政治：仅记录需求，尚无模拟或交易数据。
- 存档迁移：未来由持久化层迁移已发布 schema，防止场景脚本直接绑定历史文件格式。
- 联机：将来需要权威状态与输入意图区分；当前仅单机，不承诺现有代码直接可联网。

## 6. 已知限制与下一步建议

固定小地图、几何像素占位素材，没有声音、物品、奖励或机缘事件。敌人不绕障碍，可互相重叠；击杀不刷新、不掉落修为。升级只有数据变化，无正式属性成长。不能在正式新一世中延续冒险，也没有独立于玩家的长期世界演化。

先人工验收移动/命中/死亡/保存/关闭重开后读取。下一阶段建议先确定「凡人起步到首次突破」的一段规则与反馈（资源、收益、是否有代价），再开发一个闭环；不同时展开经营、NPC 人生和动态势力。上述建议不是自动实施授权。
